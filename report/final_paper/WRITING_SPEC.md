# Anona 正式报告写作规范

蒸馏自 [awesome-ai-research-writing](https://github.com/Leey21/awesome-ai-research-writing)
与课程交付约束。起草 `report-body.tex` 时遵守。英文工作稿见 `DRAFT_EN.md`（先英后中）。

## 术语

| 英文 | 中文 | 禁止 |
|------|------|------|
| plant（dynamics + controller） | 动力学与控制层（首次可括注 plant） | 「植物层」 |
| Anona | 工程名，正文首次注明后多用「本系统」 | 营销口号 |

## 结构

- 贡献可核验、可复现；方法主张与实验结论一致。
- 一节一个核心主张；不回避负面结果（Path H / dense_field 失败）。
- 叙事优先级：导师六项验收实验为分析主戏；Path A–H 单独成章但压缩为统一说明+对照表；任务控制台单独成章；批量规划对照等为加分。
- 目录顺序：摘要与关键词 → 目录 → 目标 → 架构 → 动力学/控制 → 仿真地图 →
  **运动规划 Path A–H（一章：共享契约 + 对照表 + 短注）** → **可视化** → **任务控制台** →
  **实验（六项配对图分析 + 加分对照）** → 开源关系 → AI 占位 → 反思。

## 规划器章节（压缩）

不再按 Path 各写四块长文。统一章节包含：

1. 共享动力学控制层契约与 homemade / vendor+桥接说明
2. 对照表列：Path、名称、自研/第三方、关联仓库、上游依赖、本仓包/桥接、类别、默认图/验收角色
3. 短注：诚实边界（D 非整仓 FUEL、F 可选、H dense FALLBACK ≠ SAC 成功）

开源关系章引用该表，不重复第二张 Path 关系表。

## 六项验收图

- 每场景一栏内 `figure`：左 RViz（`sc0N_rviz.png`），右评测曲线（`sc0N_eval.png`），宏 `\ScenarioPair`。
- 禁止整页单图；不用把六张评测图另排成独立 2×3 `figure*`。

## 语体

- 中文书面语、段落连贯；接口/参数表可用表格。
- 客观陈述；禁口语与营销腔。
- 去 AI 味：少机械连接词、少破折号、正文不用加粗刷重点。
- 保留通用英文专名（EGO、MINCO、SAC、VFH、ROS 2）。

## 图表

- 图题「图 N」、表题「表 N」；禁「本图展示了」套话。
- 表格 booktabs；数值诚实，禁止编造。
