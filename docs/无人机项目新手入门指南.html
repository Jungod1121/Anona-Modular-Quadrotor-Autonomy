无人机项目
新手入门指南

面向完全初学者：用大白话讲清楚 drone_ws 在干什么、模块怎么拼、你该测什么。 读完后，你应该能独自打开网页面板，跑通一条路径，并看懂黄线 / 蓝线。

ROS 2 Humble · Ubuntu 22.04 仓库：drone_ws 面板：http://127.0.0.1:8765/

1. 这是什么项目？

这是一个四旋翼无人机仿真工程：在电脑里模拟飞机飞、障碍物、规划路径，用 RViz / 网页面板观察结果。

作业/项目的底线可以记成三句话：

  • 自己写飞行物理（动力学）和控制器——不能拿别人的假飞机凑数；
  • 规划器可以参考/移植官方算法（EGO、GCOPTER 等），但要接到我们自己的「植物」上；
  • 模块拆开、一键启动——地图、规划、控制、可视化各干各的。
可以把它想成遥控赛车

车身 + 电机＝动力学； 遥控器追随目标＝控制器； 导航 App 画路线绕过障碍＝规划器； 赛道＝地图。导航坏了不能换电机偷懒。

2. 一张图看懂整条链路

你 / 网页 / RViz │ 「去这里」 ▼ ┌──────────┐ 障碍点云 ┌────────┐ │ 规划器 │ ◄─────────── │ 地图 │ │ A/B/C/D │ └────────┘ └────┬─────┘ │ 下一步怎么飞 │ local_goal / trajectory_cmd │ trajectory（黄线） ▼ ┌──────────┐ 电机转速 ┌──────────┐ │ 控制器 │ ─────────► │ 动力学 │ └────▲─────┘ └────┬─────┘ │ 我在哪儿？ │ flown path（蓝线） └────── odom ───────────┘

黄线＝计划飞哪； 蓝线＝实际飞了哪。 理想情况：蓝线贴着黄线走，并且不穿树。

3. 三条核心原则

原则 A：植物（Plant）不变，规划器可换

「植物」= 动力学 + 控制器。 Path A / B / C / D 换的是「大脑」写法，但都应该通过同一套输出去喂控制器。

原则 B：话题契约像电源插座

大家约定好话题名字，才能插在一起。合约坏了，就会出现「看得见飞机却不飞」「直穿障碍」这类怪事。

原则 C：不整库运行别人的模拟器

官方 EGO / GCOPTER 自带假飞机时，我们不用。 只借用规划 / 地图思想，仍驾驶自己的动力学。

4. 话题契约（最重要的表）

方向 话题 白话
动力学 → 大家 /drone/odom 飞机现在在哪、速度多少
你 → 规划器 /drone/goal 我想去的终点（RViz 2D Goal 也会发这个）
地图 → 规划器 /map/obstacles
/map_generator/global_cloud		 障碍点云（两个名字，bridge 会互相同步）
规划器 → 控制器 /planner/local_goal 近处滚动目标点
规划器 → 控制器 /planner/trajectory_cmd 位置 / 速度 / 加速度 / 航向（主流跟随对象）
规划器 → RViz /planner/trajectory 黄线计划轨迹
动力学 → RViz /drone/path 蓝线实际飞行轨迹
多机例外（EGO-Swarm）

多机时，规划目标走 /uavN/ego/goal，故意不喂给控制器的「直线冲终点」接口， 以免还没规划好就穿森林。

6. 各模块用一句话讲完

  • 动力学：假装地球上有一台真飞机在飞。
  • 控制器：努力跟上「当前应该飞到的参考点」；它本身不懂避障。
  • 地图：种一堆障碍点云；可用固定种子复现实验。
  • 规划器：看见障碍，画出绕行轨迹。
  • Bridge（如 ego_cmd_bridge）：把官方 EGO 的指令翻译成我们的控制器听得懂的话题。
  • 云桥 cloud_bridge：让「自制地图名」和「官方地图名」两边都能看到同一片障碍。
  • Dashboard：网页上选路径/地图、Start/Stop，少敲命令。

7. 四条规划路径（Path A–D）

Path A · homemade

自研规划器

自研 EGO 风格规划 + 自研 / 兼容地图。适合对照验收与调参。

Path B · ego

官方 EGO

官方 ego_planner + 官方森林/地图生成器，经 bridge 驱动我们的植物。

Path C · gcopter

GCOPTER / MINCO

更偏多项式轨迹优化的路径。植物仍是我们的。

Path D · fuel_explore

FUEL 式探索

雾面 + 前沿选目标；真正飞路仍靠 EGO（Path B 后端）。不是整仓搬运 FUEL SO3。

地图里你会看到的名字（举例）

  • dense_field — 自制稠密障碍（Path A 默认口味）
  • official_forest — 官方森林（Path B/C 常见默认）
  • official_maze2d / posts / perlin … — 官方其它场景

完整列表见仓库内 src/drone_bringup/MAPS.md。

8. 一次正常飞行，按时间顺序

  1. 点网页 Start：地图、动力学、控制器、规划器都起来。
  2. 点云障碍出现（棕色/森林点之类）。
  3. 飞机出现在起点（odom 有效）。
  4. 目标到来：自动 goal、或 RViz「2D Goal Pose」、或 Path D「开始探索」。
  5. 规划器算路 → 发出黄线 + trajectory_cmd。
  6. 控制器跟随指令 → 动力学运动 → 蓝线变长。
  7. 你对比：黄/蓝是否贴合、是否撞障碍。

9. 「直线冲目标」模式——是不是自杀？

拿来穿森林：是的，等于自杀模式。它和「要避障」的目标相反。

控制器里其实有优先级：

  1. 优先跟 /planner/trajectory_cmd（正经规划结果）；
  2. 其次跟 /planner/local_goal；
  3. 实在什么都没有时，才可能直线冲 /drone/goal。

第三条不看地图，只知道终点坐标。它存在的理由是：

  • 空旷场景验收（悬停、单点、没障碍）；
  • 规划器还没出第一帧指令时，偶尔当「暂存目标」；
  • 控制器本职是「跟踪参考」，不是「找路」——找路必须是规划器。
多机曾经踩过的坑

目标若同时发给「规划器」和「控制器直线模式」，后面几架还在等 EGO 解锁时， 会已开始直线穿林。所以 Swarm 关掉了这条 fallback，目标改走 /uavN/ego/goal。

10. 推荐：用网页面板操作（少敲命令）

  1. 终端里如需启动面板：ros2 run drone_bringup dashboard
  2. 浏览器打开 http://127.0.0.1:8765/
  3. Single：选 Path A/B/C/D + 地图 → Start
  4. Multi：选 EGO-Swarm / 同场 / 编队 → 设定机数 → Start
  5. 换场景前务必先 Stop
  6. 机数很大时，可关掉 RViz，减轻电脑负担（规划主要吃 CPU，不是指望 GPU）
本指南也可以在面板旁打开

若 dashboard 已启动，可访问 http://127.0.0.1:8765/guide.html （需把本文件同步到 dashboard_static/guide.html）。

11. 建议自测顺序（你测完把问题打给我）

  1. Path A + dense_field：有黄线、蓝线，能到目标。
  2. Path B + official_forest：能进林子且绕障。
  3. Path C + official_forest：黄线可见（不应闪一下就没）。
  4. Path D：点「开始探索」，会陆续换目标并飞。
  5. Multi → EGO-Swarm：先 2～4 架，再 10 架；应多机起飞且不是直穿障碍。

单机 RViz 提醒：Fixed Frame = map；黄线话题 /planner/trajectory；蓝线 /drone/path。

12. 发现问题怎么反馈最有用

请尽量带上：

  • 模式：A / B / C / D / Swarm（机数）
  • 地图：如 official_forest
  • 期望：例如「应绕树」
  • 现象：例如「只有 2 架起飞」「蓝线穿树」「无黄线」
  • 网页日志面板最后几行（如有 process has died / exit code -11）
